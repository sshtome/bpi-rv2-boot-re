# bpi-rv2-boot-re

Восстановление и модификация цепочки загрузки **Banana Pi BPI-RV2 V11** (SoC SiFlower SF21H8898, ядра T-Head XuanTie C908, RISC-V): реверс-инжиниринг проприетарного First Boot Loader (FBL) и перенос загрузки с NAND на NOR методом бинарного патчинга без JTAG (отладка «вслепую» через UART1).

> **Основной документ проекта:** [docs/BPI-RV2-TRM.md](docs/BPI-RV2-TRM.md) — технический справочник: аппаратура (включая JTAG-мультиплексирование с UART0 и резисторы R95–R97/R106), архитектура загрузки, реверс FBL (X/R-окна, EXSPI-диспетчер, DDR-тренировка, CSR XuanTie), методология слепого патчинга. **Рекомендуется к прочтению перед любыми экспериментами.**

---

## 1. Суть проекта

| Вопрос | Ответ |
|---|---|
| Что ломали? | Заводская плата загружается только с NAND (jumper J5 горизонтально). Проект переносит загрузку на NOR (16 МБ, EN25QH128) через собственный кастомный FBL. |
| Что такое FBL? | «SiFlower SF21H8898 Bootloader» — проприетарная vendor-стадия ddr_init (BootROM → FBL → zero_stage_boot → OpenSBI → U-Boot → Linux). Исходников DDR-инициализации в открытом доступе нет. |
| Как патчим? | Ассемблерные хуки (`src/nor_stubs.S`) внедряются в нулевые зоны бинарника FBL; абсолютные переходы кодируются плейсхолдерами DEAD000N и заполняются на этапе сборки. |
| Как отлаживаем? | Только UART1 (115200 8N1) и прошивка NOR программатором CH341A. JTAG физически есть (мультиплексирован с UART0), но в проекте не применялся. |
| Текущий статус | DDR-тренировка и чтение u-boot.itb с NOR через внутренний EXSPI-диспетчер FBL — работают. Копирование ИТБ в DDR идёт при паузах между записями (v135v3). Открытые рубежи: чтение из DDR после тренировки и прохождение парсера FIT. Полная хронология 135+ итераций — в [docs/JOURNAL.jsonl](docs/JOURNAL.jsonl). |

**Критически важные ограничения (подробности в TRM, §2–3):**

1. **IROM грузит только файл[0:0x8DA0]** (поле 0x00 заголовка — размер кода; изменять нельзя). Заголовок [0:0x70] в память не попадает (сдвиг IROM 0x70).
2. **Чексумма IROM:** `sum8[0:0x8DA0] + 0x15 (mod 256) == файл[0x08] (0x42)` → сумма должна быть 0x2D; подгонка байтом @0x7D28.
3. **NAND-FBL перезаписывать нельзя** (soft-ECC в OOB не воспроизводится программатором). Проект работает только с NOR.
4. Висы при ошибках DDR — «глухие» (исключения не генерируются, mtvec не спасает).

## 3. Сборка (пошагово)

### 3.1 Зависимости

- Toolchain RISC-V: `riscv64-linux-gnu-gcc`, `riscv64-linux-gnu-objcopy` (или XuanTie GNU Toolchain из SDK).
- Python 3.
- Linux-окружение или WSL (скрипт использует bash).

### 3.2 Сборка кастомного FBL

```bash
# из корня репозитория
wsl bash scripts/build.sh 42          # номер варианта = номер гипотезы
# или без WSL, на Linux:
# bash scripts/build.sh 42
```

Скрипт выполняет:
1. **Подготовку базы** из `bin_orig/fbl.bin`: патч поля размера @0x0C → 0x203E8 + догрузка хвоста `fbl_v2_tail.bin` (точное воспроизведение исторической базы v2).
2. **Компиляцию** `src/nor_stubs.S` (секции `.text.normini`, `.text.ddrload`, `.text.dbg`).
3. **Внедрение** кода в файл: nor_read@0x0D08, ddr_load@0x035C, dbg-код в rodata-паддинг @0x7DAC; патчи-переходы (P1@0x356, P-DDR@0x4B40, хук printf@0x5B24, nor_read_emul@0x0DC2 и др.); заполнение плейсхолдеров DEAD000N.
4. **Пересчёт чексуммы IROM** (формула в шапке скрипта; независимая проверка утилитой `irom_checksum.py`).
5. **Сборку полного NOR-образа** 16 МБ: FBL @0x0 (с 0xFF-паддингом), u-boot.itb @0x40000.

Результаты: `build/custom_fbl_<TAG>.bin`, `build/nor_full_<TAG>.bin`.

### 3.3 Прошивка NOR (программатор CH341A)

1. Установите jumper **J5 вертикально** (выбор NOR для BootROM).
2. Подключите CH341A к NOR U24 (Eon EN25QH128, распайка 8-pin стандартная).
3. Прошейте `build/nor_full_<TAG>.bin` (или только `custom_fbl_<TAG>.bin` в 0x0) любым клиентом CH341A (AsProgrammer / flashrom / SNANDer).
4. Подключите UART1 (0x0C301000, 115200 8N1, 3.3 В TTL), подайте питание.

Ожидаемый лог успешной стадии: `IROM DONE!` → `..<TAG>DDR init for 4096 Mb RAM...` → далее маркеры варианта (расшифровка маркеров — в JOURNAL.jsonl и TRM §4.4).

## 4. Происхождение базы и артефактов

- `bin_orig/fbl.bin` извлечён из заводского NAND-образа `openwrt-...-nand-squashfs-fullflash.img` (смещение 0x0–0x20000; заголовок «sa18», сборка Feb 28 2025).
- `bin_orig/uboot.itb` извлечён из UBI-области того же образа (магия FIT `d00dfeed`).
- `bin_orig/fbl_v2_tail.bin` — хвост 1000 байт (0x3E8) исторической базы `custom_fbl_v2.bin` (132 072 б = 0x203E8): код-стабы (0x1C025136/5204/523C/5240/534A), на которые база v2 перенаправляет 5 JAL-вызовов парсерной зоны (0x1C007C46, 0x1C007572, 0x1C007B0C ×2, 0x1C007592). Эти патчи воспроизводятся `make_base()` в `scripts/build.sh` (список `V2_PATCHES`, сверен побайтово: сборка из этого репозитория идентична исторической).
- `docs/fbl_full_vma.dis` — дизассемблер с базой VMA 0x1C005000. Трансляция: `файл = dis − 0x1C005000`; реальная память `файл[X] → 0x1C004F90 + X` (код) или `0x1C005000 + X` (зона ≥0x8DA0). См. `scripts/enc_j.py`.

## 5. Как вносить новые гипотезы

1. Добавить вариант в `src/nor_stubs.S` под `#if defined(VXXX)` и в таблицу вариантов `scripts/build.sh` (TAG/VNUM/DEF).
2. Собрать: `wsl bash scripts/build.sh <номер>`.
3. Проверить: чексумма (вывод скрипта), FIT-магия @0x40000, байты патчей по дизассемблеру.
4. Прошить, снять лог UART, записать результат в `docs/JOURNAL.jsonl` (формат: timestamped JSONL-записи) и обновить TRM при новых установленных фактах.

**Правила безопасности:** не перезаписывать NAND-FBL; не менять поле 0x00 заголовка; патчить только смещения >0x70; dbg-код — только в нулевой паддинг [0x7DAC:0x8DA0] (грузится IROM сразу); дескриптор EXSPI — по 0x1C00D600 (пересечение с буфером зоны вешает шину).
