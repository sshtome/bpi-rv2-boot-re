# bpi-rv2-boot-re — Загрузчик SPI NOR для Banana Pi BPI-RV2

**Автор:** sshtome for 4PDA  
**Статус проекта:** Завершено · Полностью рабочий релиз v157  
**Целевая платформа:** Banana Pi BPI-RV2 V11 (SoC SiFlower SF21H8898, 4× RISC-V T-Head XuanTie C908 @ 1.25 ГГц, 512 МБ DDR3 @ 1066 МГц)

Полноценная альтернативная цепочка загрузки для одноплатного компьютера **Banana Pi BPI-RV2** со штатной микросхемы SPI NOR флеш-памяти (U24, Eon EN25QH128, 16 МБ) в обход заводской NAND-памяти:
`BootROM (IROM) -> custom FBL (v157) -> OpenSBI v1.5 -> U-Boot 2022.10 (sf21h88>)`.

---

## 1. Назначение и предыстория

На заводской плате Banana Pi BPI-RV2 загрузка по умолчанию выполняется исключительно с микросхемы SPI NAND (U14, Winbond W25N01GVZEIG, 128 МБ, джампер J5 горизонтально). 

Вендорный First Boot Loader (FBL) в NAND записан с использованием программной коррекции ошибок (soft-ECC) в OOB-области страниц. Обычные программаторы (включая популярный CH341A) не способны корректно прошить этот раздел, что при повреждении заводского загрузчика приводило к окирпичиванию устройства без возможности простого восстановления.

Данный проект решает эту проблему:
1. Загрузка перенесена на отдельную микросхему **SPI NOR флеш** (U24, 16 МБ), которая поддерживается стандартным недорогим программатором CH341A без нюансов с OOB/ECC.
2. Проведен реверс-инжиниринг бинарного блоба инициализации памяти вендора (FBL).
3. Устранены критические ошибки вендорного кода, блокировавшие работу контроллера памяти при загрузке с альтернативного чипа.
4. Обеспечен автоматический запуск **OpenSBI v1.5** и переход в командную строку **U-Boot 2022.10** (`sf21h88>`).

## 2. Ключевые исправления релиза v157

- **Калибровка DDR3 PHY (смещение 0x8E10):** устранен дефект вендорного кода вычисления смещения калибровочных таблиц; тренировка задержек и выравнивание шины проходят полностью и стабильно.
- **Редирект CS1 -> CS0:** обращения к регистрам CS1 перенаправлены на CS0 в соответствии с топологией платы.
- **Обход проверки хэша прошивки DDR (0x43AC):** устранено ложное срабатывание integrity check при модификациях FBL.
- **Перевод контроллера UMCTL2 в Normal Mode:** реализован опрос готовности PHY и перевод контроллера памяти в рабочий режим (`Operating Mode = 0b001`).
- **Активация 4 портов AXI Slave:** снята блокировка портов контроллера (`0xD0000490..0x6A0`), что устранило зависания серийных операций чтения/записи DDR (`0x20000000..0x3FFFFFFF`).
- **Чистый стоковый libfdt:** устранены устаревшие хаки парсинга дерева устройств; парсер FIT-образа `uboot.itb` работает штатно.
- **Автоматическая передача управления:** OpenSBI и U-Boot корректно размещаются в оперативной памяти с передачей DTB через регистр `a1`.
- **Чистый релизный вывод:** консоль очищена от массивного отладочного мусора, добавлен лаконичный идентификатор релиза `by sshtome for 4PDA`.

## 4. Сборка прошивки

### Требования к окружению

- Кросс-компилятор RISC-V: `riscv64-linux-gnu-gcc`, `riscv64-linux-gnu-objcopy` (пакет `gcc-riscv64-linux-gnu` в Ubuntu/Debian).
- Python 3.8+.
- Linux или WSL на Windows.

### Процесс сборки

Сборка выполняется одной командой из корня репозитория:

```bash
./scripts/build.sh
```

Или напрямую через Python:

```bash
python3 scripts/build.py
```

В результате в каталоге `build/` формируются:
- `build/nor_full.bin` — полный 16 МБ образ для микросхемы SPI NOR флеш (содержит кастомный FBL со смещения 0x0 и FIT-образ `uboot.itb` со смещения 0x40000).
- `build/custom_fbl.bin` — бинарник модифицированного первичного загрузчика FBL (с корректной контрольной суммой заголовка IROM).

## 5. Прошивка и запуск платы

### 1. Настройка переключателей
Переведите джампер **J5 на плате BPI-RV2 в вертикальное положение** (выбор микросхемы NOR для внутреннего BootROM SoC).

### 2. Запись прошивки программатором
1. Подключите программатор CH341A (прищепкой или через переходник) к микросхеме **U24 (Eon EN25QH128)**.
2. Запишите файл `build/nor_full.bin` начиная со смещения `0x00000000`.
   *(Для записи подходит любая утилита: `flashrom`, `AsProgrammer`, `NeoProgrammer` или `SNANDer`).*

### 3. Подключение консоли UART
- Подключите USB-UART адаптер к разъему UART1 платы:
  - TX адаптера -> RX платы
  - RX адаптера -> TX платы
  - GND адаптера -> GND платы
- Параметры терминала: **115200 бод, 8 бит данных, без четности, 1 стоп-бит (8N1)**.

### 4. Включение питания
Подайте питание 5V/3A через порт Type-C.
