# FBL (SiFlower SF21H8898 Bootloader) — полный разбор

> Реверс-инжиниринг первого загрузчика платы Banana Pi BPI-RV2.
> Файл: `fbl.bin` (131 072 байта, извлечён из `fullflash.img`, смещение 0x0–0x20000).
> Баннер: «SiFlower SF21H8898 Bootloader (Feb 28 2025 - 22:46:57)».

---

## 1. Обзор

| Параметр | Значение |
|---|---|
| Архитектура | RISC-V rv64 (imafdc**bx** — есть T-Head/Xuantie расширения) |
| Размер | 128 КБ (0x20000) |
| Базовый адрес (load address) | **0x1c005000** (подтверждено заголовком и ссылками `lui 0x1c00x` в коде) |
| Виртуальный адрес | file_offset + 0x1c005000 |
| Стек | `lui sp, 0x1c005` → sp = 0x1c005000 (растёт вниз, ниже кода) |
| Формат | raw binary с заголовком `sa18` |

Файл дизассемблинга: `fbl_full_vma.dis` (objdump, `-b binary -m riscv:rv64 --adjust-vma=0x1c005000`, ~19 700 строк).

## 2. Заголовок (0x1c005000–0x1c00506f)

| Смещение | Байты | Значение | Интерпретация |
|---|---|---|---|
| +0x00 | `a0 8d 00 00` | 0x8da0 = 36 256 | размер кода+rodata (~36 КБ) |
| +0x04 | `73 61 31 38` | **`sa18`** | магия (кодовое имя SoC) |
| +0x08 | `42 98 00 00` | 'B' + 0x98 | вариант платы/конфигурации |
| +0x0c | `00 00 02 00` | 0x20000 | полный размер образа (128 КБ) |
| +0x10 | `00 50 00 1c` | 0x1c005000 | адрес загрузки |
| +0x14 | `00 50 00 1c` | 0x1c005000 | адрес загрузки (дубль) |
| +0x1c | `01 00 00 00` | 1 | флаг |
| +0x28 | `00 c2 01 00` | 0x1c200 = 115200 | скорость UART |
| +0x48 | `20 03 00 00` | 0x320 = 800 | параметр |
| +0x50 | `00 40 00 00` | 0x4000 = 16 КБ | параметр |

Код начинается с +0x70 (точка входа). Заголовок читает ROM (IROM) при загрузке.

## 3b. ВАЖНО: база исполнения FBL = 0x10000000 (не 0x1c005000!)

Установлено железом (v54/v55, хук printf): первый вызов printf идёт из адреса **0x1000002F**,
т.е. IROM грузит образ FBL и исполняет его по базе **0x10000000**, а **0x1c000000 — алиас
той же SRAM** (запись по 0x1c005000+X == запись по 0x10000000+X, поэтому патчи по
0x1c00-адресам работают). Дизассемблер с базой 0x1c005000 верен ПО СМЕЩЕНИЯМ:
VMA = файл + 0x1c005000; реальный адрес исполнения = файл + 0x10000000.

**ЗАГАДКА (v55):** первый printf из 0x1000002F печатает строку «test ok! addr:0x20000000
value:0x5a» (a0 = 0x1c00c978, середина w1b-строки +8). НО в файле по смещению 0x2F — ДАННЫЕ
заголовка (0x0A 00 00 00), а в памяти там исполняемый код ⇒ IROM грузит/исполняет образ
не так, как мы моделировали (возможен сдвиг). «N3» («Now DDR3») печатается НЕ через
printf(0x1c00ab24). Уточняется дампом памяти (v57).

## 4. Периферия (MMIO, из lui-ссылок кода)

| Устройство | Адрес | Использование |
|---|---|---|
| **EXSPI** (SPI flash) | 0x0c200000 | контроллер SPI, через него и NAND, и NOR |
| **UART0** (PL011) | 0x0c300000 | консоль |
| **UART1** (PL011) | 0x0c301000 | консоль (FR@+0x18 бит 0x80 = TXFE, DR@+0x00) |
| **CRU** (clock/reset) | 0x0ce00000 | тактирование (CLK_CFG @0xce0048c, +0xce004a0, +0xce00500, 0xce09800) |
| **DDR-контроллер** | 0xce000000 | регистры DDR (0xce0048c, 0xce0049c, 0xce00500…) |
| **DDR PHY** | 0xd0000000 | конфиг таймингов (0xd000304, 0xd000030…) |
| **DDR PHY (тренировка)** | 0xa0000154…0xa04417c | регистры этапов тренировки (ядро 0x1c008f5a) |
| **Периферия тестов** | 0x30300000 / 0x40540000 / 0x66099000 | w2b/w4b/w8b-тесты в хвосте DDR-инициализации |

### Регистры EXSPI (протокол из u-boot sf_exspi.c)

| Регистр | Смещение | Поля |
|---|---|---|
| CR0 | 0x000 | конфиг |
| CR1 | 0x004 | **SSE = бит 1** (включение) |
| DR | 0x008 | данные (команда+адрес пишутся сюда) |
| SR | 0x00C | TFE=0, TNF=1, RNE=2, RFF=3, BSY=4 |
| CPSR | 0x010 | статус |
| EXSPI_CMD0 | 0x02C | 0x8000 \| cmd_nbytes \| addr_count<<1 = 0x8007 |
| CMD1 | 0x030 | rx << 4 |
| CMD2 | 0x034 | = 0x15 |

Чтение NOR: команда 0x03 + 3 байта адреса в DR → SSE → поллинг RNE → данные. Чанки ≤ 256.

### Кастомный CSR

`csrsi 0x7c1, 3` (функция 0x1c008816) — выполняется сразу после DDR-инициализации (включение кэшей/рабочего режима).

Ключевой факт для NOR-адаптации: **SPI-контроллер EXSPI общий для NAND и NOR** — FBL уже умеет им управлять.

## 5. Поток загрузки (что делает FBL)

### 5.1 Entry (0x1c005070)
```
jal 0x1c005084      → startup (очистка BSS 0x1c007d28–0x1c0094b8,
                     используется T-Head custom-инструкция 0x7883500b)
lui sp,0x1c005      → стек = 0x1c005000
li a0,0
j 0x1c006382        → main
wfi                 → idle-петля (если main вернётся)
```

### 5.2 main (0x1c006382)
1. `jal 0x1c0037dc`, `jal 0x1c006086`, `jal 0x1c005f28` — ранняя инициализация;
2. **Pinmux**: многократные `jal 0x1c005caa` / `0x1c005df6` / `0x1c005dce` с (a0=пин, a1=функция) — настройка выводов (pad set func; в FBL есть строка `sf_pad_set_func error!`);
3. `jal 0x1c003938`, `jal 0x1c003a54`, `jal 0x1c000348`, `jal 0x1c006370`, `jal 0x1c004af8`, `jal 0x1c003816` — инициализация (UART в 0x1c008900+);
4. **Цикл опроса** (0x1c006424–0x1c006480): `jal 0x1c005b24` → `jal 0x1c00334e` → … → `jal 0x1c00337a` → `j 0x1c006424` — бесконечный цикл (вероятно, ожидание завершения DDR-тренировки, которая идёт асинхронно).

Дальнейшая цепочка (печать баннера, `SPI-NAND got mfr_id`, UBI, загрузка u-boot, прыжок) выполняется внутри вызываемых функций — для полной карты нужен следующий этап реверса (построение графа вызовов и привязка строк к функциям).

### 5.3 Ключевые строки (rodata) и их адреса

| Адрес | Строка |
|---|---|
| 0x1c00b5f0 | `SPI-NAND got mfr_id: %x, dev_id: %x` |
| 0x1c00bef8 | `UBI: Loading VolId #%d` |
| 0x1c00c4c8 | `Jump to u-boot at 0x%08lx...` |
| 0x1c00c908 | `DDR init for %lu Mb RAM...` |
| 0x1c00ccf8 | `SiFlower SF21H8898 Bootloader (%s - %s)` |

## 7. Оценка адаптации FBL под NOR

### Что благоприятно
- **EXSPI общий** для NAND и NOR: у FBL уже есть драйвер SPI-контроллера (0x0c200000).
- FBL уже умеет: DDR-инициализацию, распаковку FIT (строки `Loding standalone/firmware/flat_dt`, `compression`, `lzma`), прыжок в u-boot (`Jump to u-boot`).
- Значит, для NOR нужно заменить **только** источник данных u-boot: вместо «монтируем UBI и читаем том 0» — «читаем u-boot.itb с NOR по фиксированному смещению командой SPI-read (0x03)».

### Что мешает / риски
1. FBL **не содержит NOR-кода**: есть только SPI-NAND (soft-ECC) + UBI. NOR-read (0x03/0x0b) придётся писать самому (через регистры EXSPI) и вшивать патчем.
2. **Возможна подпись**: в SDK SiFlower есть `keyfile`/`manage_sig.sh`. Если ROM проверяет подпись FBL — патч не пройдёт. (Не проверено.)
3. Патч RISC-V-кода вручную — трудоёмко и рискованно (ошибка = не стартует; но FBL в NAND, можно аккуратно тестировать).

### Вывод
Адаптация **теоретически возможна** (заменить «UBI→u-boot» на «NOR→u-boot»), но это серьёзная RE+патч задача. Более быстрый путь к NOR-загрузке — готовый NOR-FBL (дамп с NOR-версии платы).

## 7b. Результаты декомпиляции (Ghidra 11.3.1)

Полный псевдокод: **`fbl_decompiled.c`** (164 функции, 5016 строк). Ниже — расшифрованный поток.

### Точка входа и main

```c
void FBL_entry(void) {              // 0x70
  FUN_00000084();                   // startup: очистка BSS 0x7d28–0x94b8
  FUN_00006382(0);                  // main
}

undefined8 FUN_00006382(...) {      // main (0x6382)
  FUN_000037dc();                   // init
  _DAT_0ce004a0 |= 0x2c000000;      // CRU: включение тактовых
  _DAT_0ce0048c |= 0xf0317f;        // CRU: CLK_CFG (= u-boot CLK_CFG 0x80067F-регион)
  FUN_00005caa/5df6/5dce(...);      // pinmux (пины 0x15–0x22, 0xb, 0xc, 2)
  FUN_00003938(); FUN_00003a54(1);  // init (UART)
  FUN_00000348();
  do {                              // бесконечный цикл
    FUN_00004af8();                 // DDR init (большая, ~373 строки)
    FUN_00003816();
    FUN_00005b24(0x1c00cc88,0x1c00cc78,0x1c00cc68); // printf(banner, дата, время)
    if (FUN_0000334e() == 0)        // DDR-тренировка прошла
      FUN_0000337a();               // === ЗАГРУЗКА U-BOOT ===
  } while(true);
}
```

### Функция загрузки u-boot — FUN_0000337a (0x337a) — цель патча для NOR

```c
long FUN_0000337a(void) {
  if (_DAT_21a00000 != 0xD00DFEED) return -0x16; // проверка МАГИИ FIT!
  FUN_00002c46(&DAT_21a00000, 0x1c00c300);       // UBI attach ("UBI: Loading VolId #%d")
  FUN_00002572(...);                              // UBI: поиск тома 0
  FUN_00002b0c(...);                              // UBI: чтение LEB
  FUN_000031ce/31da/3242(...);                    // разбор FIT
  FUN_00003320 / (*pcVar8)(0,pcVar7);             // загрузка (u-boot→0x20000000,
                                                  // OpenSBI→0x3fe00000, DTB→0x3ff00000)
                                                  // и ПРЫЖОК в u-boot
}
```

Строковые аргументы подтверждают: 0x1c00c300 = «UBI: Loading VolId #%d», 0x1c00c330 = «UBI warning: Failed», 0x1c00c458 = «Jump to u-boot at 0x%08lx».

### Вывод для NOR-адаптации (конкретный план)

Патчить нужно **FUN_0000337a (0x337a)**: заменить UBI-чтение (`FUN_00002c46/2572/2b0c`) на чтение u-boot.itb с NOR по фиксированному смещению (SPI-команда 0x03 через EXSPI `0xc200000`, данные → 0x21a00000). Всё остальное (проверка магии FIT, разбор FIT, прыжок) **не трогаем**.

## 7c. РАБОЧИЙ протокол чтения NOR (через диспетчер) — доказан железом

Прямые записи в регистры EXSPI (v19–v21) данных НЕ дали. Рабочий путь: наш код заполняет **дескриптор** в памяти и вызывает **живую функцию-диспетчер** `0x1c005dd4` (в кластере детекта be6 — НЕ затирать!). Диспетчер сам выполняет транзакцию EXSPI.

**Дескриптор** @0x1c00e000:

| Смещение | Значение |
|---|---|
| [0] | 0x03 (команда READ) |
| [8] | адрес NOR |
| [16] | 0 |
| [24] | 0 |
| [32] | длина |
| [40] | буфер-приёмник |
| [48] | 0 (обязательно! без него диспетчер виснет на мусоре — баг v40) |

Вызов: `a0 = 0x1c00e068` (дескриптор+104), `a1 = 0x1c00e000` (дескриптор), `jal ra, 0x1c005dd4`.

**Подмена таблицы команд** (до вызова): `[0x1c00d860+26] = 0x03`, `[0x1c00d860+28] = 0x00`. Таблица в файле — вся нули (заполняется в рантайме). После каждого вызова: `CR1 = 0` (0xc200004, выключение SSE).

Ограничения (выявлены по логам v36–v49):
- Чанки ≤ 256 байт. Состояние цикла — ТОЛЬКО в callee-saved s-регистрах + пролог (t-регистры диспетчер портит — баг v36–v41).
- Вызовы C-функций — только `jal ra` + сохранение своего ra в стеке, иначе адрес возврата теряется (баг v42/v45: ret улетал в середину цикла → вечное мусорное чтение).
- **Регистрам, восстановленным из стек-кадра после вызова диспетчера, НЕ доверять** (кадр повреждается — баг v48: lw по «восстановленному» s1 вешал шину).
- Задержка перед первым чтением НЕ нужна (v42 с задержкой 10с молчал по jal-ra-багу).

## 7d. DDR: карта потока FUN_00004af8 и DDR-зона

**DDR-зона файла [0x8da0:0x20000] — ДАННЫЕ, не код** (81% нулей, dis — мусор, jalr в код FBL один — переход в u-boot). IROM на NAND грузит её в 0x1c00dda0+; на NOR — НЕ грузит (наш ddr_load дочитывает). **Важно: 0x1c00e-область (0x1c00e000–0x1c01f000) — часть зоны** (файл 0x9000–0x20000): там рабочие таблицы тренировки:
- 0x1c00e298 — таблица частот (код 0x1c008f5a сравнивает с 469/625/937/1249/1875 МГц);
- 0x1c00e0f0 — переменная частоты (туда пишется код частоты: 1066 МГц = 0x08550000, в память кладётся как (x>>20)<<3 = x>>17);
- 0x1c00d860 — таблица команд SPI-диспетчера (в файле нули);
- 0x1c00e340 — буфер puts-вывода.

**Поток FUN_00004af8 (0x1c009af8, пролог sp-112):**
1. printf(0x1c00c898, 0x1000) «ERROR: DDR freq %dMHz not support!!!» — БЕЗУСЛОВНО, в начале; вывод теряется (ранняя стадия UART). На этом вызове стоит наш P-DDR (файл 0x4b40).
2. Конфиг контроллера (0xce000000) + PHY (0xd0000000).
3. `jal 0x1c008f5a` — ядро тренировки (PHY 0xa0000154–0xa04417c), возвращает код частоты.
4. Поллинг DDR: запись 0 в 0x20000000 → чтение → цикл 29 попыток; результат в 0x1c00e0f0; сравнение (x>>17) == s9.
5. Цикл подбора частоты: не сошлось → puts(0x1c00c8b8 «…Use default value…») → s9 = нормализованная частота → j 0x1c009b3a (повтор). Сошлось (s9=1066) → печать 0x1c00c8e0 «Now DDR3 frequency is: 1066MHz!!!» (0x1c00a31e).
6. Тесты: sb 'Z' в 0x20000000 → lbu (w1b/r1b), sh 0x5aa7 в 0x30300000 (w2b/r2b — ВНУТРИ DDR 512 МБ, работает), sw 0x5aa71342 в **0x40540000** (w4b) и sd в **0x66099000** (w8b) — **вне DDR, на NOR-пути НЕ включены → вешают шину** (стоп v49). Печати тестов: «ddr wNb test ok!» 0x1c00c970+, «read value is» 0x1c00c9a0.
7. Эпилог (0x1c00a40a): ret с a0 = код частоты.

После FUN_00004af8: jal 0x1c008816 (`csrsi 0x7c1,3`) → printf(0x1c00cc88, cc78, cc68) «…### ERROR ### Please RESET the board ###» → FUN_0000334e (main-цикл загрузки u-boot).

**Хроника NOR-загрузки (кастомный FBL):** v4 (стоп на DDR — тест мешал), v19–v21 (прямой EXSPI — нет данных), v34–v35 (одиночный вызов диспетчера ✓), v36–v41 (фиксы дескриптора/t-регистров), v42–v45 (jal-ra-баг — тишина), v46 (фикс jal-ra: DDR-тренировка дошла до «Now DDR3»), v47–v48 (маркеры строк; lw-баг), v49 (тренировка ПРОШЛА, тесты w1b/w2b ✓, стоп на 0x40540000), v50 (пропуск w4b/w8b → дальше).
